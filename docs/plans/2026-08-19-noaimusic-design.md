# NoAI Music — 설계 (2026-08-19)

## 의도 (한 문장)
유튜브로 음악을 듣는 사람의 추천·검색·자동재생에서 AI 생성 음악 플레이리스트를,
재생 흐름을 한 순간도 끊지 않고, 보이지 않게 걸러낸다.

- 카테고리: 콘텐츠 필터 (광고차단기형) / 혼동하기 쉬운 옆 카테고리: 커뮤니티 신고 플랫폼(ByeAI형 — 의도적으로 배제)
- 타깃: 유튜브로 음악을 매일 듣는 한국어 사용자 (1호 사용자 = 제작자 본인)
- 대상 스코프: **음악 콘텐츠만** 판별·차단. 일반 영상은 절대 건드리지 않는다.
- 적용 범위: youtube.com 홈 피드 · 검색 결과 · 시청 페이지 사이드바 · 자동재생 큐. (YouTube Music 제외)

## 핵심 요구사항 (사용자 확정)
1. AI 음악 플레이리스트가 추천목록에 아예 뜨지 않는다.
2. 자동재생이 AI 영상으로 넘어가지 않는다 — **물흐르듯, 일시정지·깜빡임 없이**.
3. 계속 새로 생기는 채널·음원도 실시간으로 걸러진다 (블록리스트 후행 방식 금지).
4. 애드블록처럼 피드백: 툴바 배지에 이 페이지에서 거른 개수, 팝업에 오늘/누적 통계 + 최근 걸러진 목록.
5. 오류 없이 — 판별 코드가 실패해도 유튜브는 원래대로 동작해야 한다.

## 판별: 4층 구조 (위에서부터 순서대로 판정, 먼저 걸리면 종료)
1. **허용목록** (사용자) → 무조건 표시. 오탐 구제.
2. **차단목록** — 사용자 차단 채널 + 시드 DB(Soul Over AI 스냅샷, 채널 ID 1,277건, CC BY 4.0 출처 표기) → 차단.
3. **휴리스틱 (2단계)** — 렌더링/응답 시점마다 실시간 평가:
   - 관문: 음악 콘텐츠인가? (제목·채널명의 음악 신호 키워드 한/영, 또는 장시간 영상 + 음악 문맥). 아니면 **무조건 통과**.
   - 판정: AI 신호가 있는가? (\bAI\b·A.I.·Suno·Udio·"AI generated"·"AI 노래"·"인공지능 작곡" 등 단어 경계 매칭)
4. **채널 프로파일링 (lazy)** — 음악 관문은 통과했으나 AI 신호가 애매한 처음 보는 채널만, 백그라운드에서 채널 페이지 1회 fetch: 비인간적 업로드 패턴(장시간 믹스 대량 업로드), 설명의 AI 도구 언급, 유튜브 "변형·합성 콘텐츠" 라벨. 공식 아티스트 채널 배지는 자동 허용 신호. 판정은 채널 ID 단위로 storage 캐시 → 채널당 1회 비용.

## 아키텍처: 데이터 레이어 필터링 (핵심 결정)
DOM에서 숨기는 방식만으로는 자동재생을 못 막는다(YouTube 자동재생은 DOM이 아니라 내부
응답 데이터를 쓴다). 그래서 **MAIN world 스크립트가 데이터 원천을 필터링**한다:

- `window.ytInitialData` — Object.defineProperty로 세터 후킹 (document_start, 인라인 스크립트가 값을 넣기 전에 설치)
- `window.fetch` 래핑 — `/youtubei/v1/next`(사이드바+자동재생 큐)·`/youtubei/v1/browse`(홈·연속 로드)·`/youtubei/v1/search` 응답 JSON을 재귀 워크로 순회, 비디오형 객체(videoId+title 보유)를 추출해 판별, 차단 판정이면 배열에서 제거. 자동재생 세트(autoplaySet)의 대상이 차단되면 첫 번째 정상 추천으로 교체.
- **안전 원칙**: 모든 후킹은 try/catch — 파싱 실패·구조 변경 시 원본을 그대로 반환. 필터가 죽어도 유튜브는 멀쩡해야 한다.

컴포넌트:
- `src/heuristics.js` — 순수 판별 로직. MAIN world·ISOLATED world·node 테스트 3곳에서 공유 (globalThis 부착 + module.exports 겸용).
- `src/page.js` (MAIN world, document_start) — 위 데이터 후킹. 걸러낸 항목 메타데이터를 window.postMessage로 content에 통지. 차단/허용 목록은 content가 postMessage로 내려줌 (도착 전엔 휴리스틱+시드만으로 동작).
- `src/content.js` (ISOLATED, document_start) — storage에서 설정·목록 로드 → page에 전달. DOM 숨김 2차 안전망(MutationObserver). 직접 링크로 차단 영상에 들어간 경우 배너 표시(강제 스킵 아님 — 사용자가 직접 연 것은 존중). 채널 프로파일링. 통계 집계 → background 전송.
- `src/background.js` (SW) — 탭별 배지 카운트, 일별 통계, 최근 감지 로그(50건 캡), 자정 리셋.
- `popup/` — 켜기/끄기, 오늘/누적 카운트, 최근 걸러진 목록(각 항목에 "허용" 버튼), 차단·허용 채널 관리, 시드 DB 온/오프.

저장: 설정·사용자 목록 = storage.sync / 통계·로그·프로파일 캐시 = storage.local. 시드는 번들 JSON(storage 미적재).

## 자동재생 보장 시나리오
- 정상 흐름: /next 응답에서 AI 항목이 이미 제거됨 → 자동재생은 항상 정상 영상으로. 사용자는 아무것도 느끼지 못한다.
- 데이터 필터가 놓친 경우(직접 링크·신규 판정 지연): 시청 페이지에서 판정되면 상단에 조용한 배너("이 채널은 AI로 판별됨 — [차단] [허용]")만. 재생 중단 없음.

## 뺀 것과 이유
- 커뮤니티 신고 서버 — ByeAI 콜드스타트 실패 재현 방지 + 운영 난이도(§13). 전부 로컬.
- Warnlist(경고 오버레이 3단) — v1 단순화. 차단/허용 2단이면 충분.
- YouTube Music 지원 — DOM·데이터 구조가 달라 별도 구현. 수요 확인 후.
- LLM API 판별 — 비용·지연·키 관리. 휴리스틱+프로파일링으로 충분한지 실사용 후 판단.
- surasshu 블록리스트 번들 — 라이선스 미확인. 확인되면 v2 시드로.
- 강제 스킵(재생 중단 후 이동) — "물흐르듯" 요구와 충돌. 데이터 레이어 필터로 대체.

## 테스트
