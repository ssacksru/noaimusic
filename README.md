# NoAI Music

유튜브 추천·검색·자동재생에서 **AI로 만든 음악 플레이리스트만** 걸러내는 크롬 익스텐션.
일반 영상은 건드리지 않는다.

## 설치

1. `chrome://extensions` → 우측 상단 **개발자 모드** 켜기
2. **압축해제된 확장 프로그램을 로드** → 이 폴더 선택
   (배포본을 쓰려면 `npm run build` 로 만든 `dist/noaimusic-*.zip` 을 풀어서 그 폴더를 선택)
3. 유튜브를 열면 툴바 아이콘 배지에 이 페이지에서 걸러낸 개수가 표시된다

## 어떻게 걸러내나 — 5층 판별

순서대로 판정하고, 먼저 걸리면 거기서 끝난다.

1. **허용목록** — 내가 허용한 채널은 무조건 표시 (오탐 구제)
   차단·학습한 채널의 **유튜브 자동생성 "믹스"와 재생목록**도 함께 걸러낸다 —
   믹스는 채널 ID가 없어 채널 차단으로 안 잡히는데, 누르면 그 채널 음악이 연속 재생된다.
2. **차단목록 + 시드 DB** — 내가 차단한 채널 + 알려진 AI 채널 1,533개
   (Soul Over AI 스냅샷 1,277 + 유튜브 AI 공시로 직접 수집한 채널 256)
3. **휴리스틱** — 카드가 그려지는 순간마다 제목·채널명 실시간 검사.
   한국어·영어뿐 아니라 스페인어·포르투갈어(IA)·독일어(KI)·프랑스어(IA)·러시아어(нейросеть·искусственный интеллект)·
   일본어(AI生成·#ai)까지 본다. 튜토리얼·리뷰·"AI 아님" 표기는 각 언어에서 통과시킨다.
   음악 관문(음악 콘텐츠인가?)을 통과한 것만 AI 신호를 본다 → 일반 영상은 애초에 대상이 아니다.
   목록에 없는 **새로 생긴 채널·음원도 그 자리에서** 걸러진다.
4. **채널 프로파일링 (학습)** — 음악인데 AI 신호가 없는 처음 보는 채널은, 백그라운드에서
   그 채널 영상 한 편의 시청 페이지를 받아 **유튜브 자체 AI 공시 배지**를 확인한다.
   판정은 채널 단위로 영구 캐시 → 채널당 1회 비용. 쓸수록 목록이 커진다.
5. **재생 시점 최후 판별** — 그래도 새어 나와 재생이 시작되면, 유튜브 AI 배지를 읽고
   **즉시 다음 정상 영상으로 넘긴다.** 그 채널은 그 자리에서 학습되어 이후 피드에서 사라진다.
   다음 곡도 AI면 계속 넘어간다(최대 10회).

### 유튜브 표시 말고 다른 신호는 없는가

찾아봤다. 확실한 AI 채널 42개와, **같은 검색어에서 나온 사람이 만든 플레이리스트 채널
60개**를 받아 특징을 비교했다(2026-08-20). 공식 아티스트 채널과 비교하면 "뮤비 대
플레이리스트" 차이를 "사람 대 AI" 차이로 착각하게 되므로 같은 장르끼리 맞췄다.

| 신호 | 검출률 | 오탐률 | 쓸 수 있나 |
|---|---|---|---|
| **해시태그 22개 이상** | 31% | 2% | ⭕ 보조로 |
| 설명글에 spotify/apple 링크 | 29% | 7% | △ |
| 영상 2시간 이상 | 64% | 48% | ✗ 사람 플레이리스트도 길다 |
| 태그 30개 이상 | 50% | 30% | ✗ |
| 저작권 문구 | 52% | 28% | ✗ |
| 설명글 1500자 이상 | 19% | 10% | ✗ |

**분위기·장르·길이로는 구분되지 않는다.** 사람이 만든 플레이리스트도 3시간짜리에
태그를 잔뜩 달고 저작권 문구를 넣는다. 유일하게 쓸 만한 것이 해시태그 수인데,
그마저 AI 의 31%만 잡고 사람 채널 2%를 오탐한다.

그래서 이 신호는 **유튜브 공시가 없을 때만** 보조로 쓰고, 팝업에서 "정황으로 추정"
이라고 구분해 표시하며 끌 수 있게 했다. 판별의 중심은 여전히 유튜브 자체 공시다.

참고로 검색·피드 데이터에도 설명 스니펫이 오지만 96자에서 잘려 해시태그가 최대
5개까지만 보인다. 그래서 이 신호도 시청 페이지를 받아야 쓸 수 있다.

### 왜 키워드만으로는 안 되는가

수집한 AI 채널 255개의 **이름을 전수 조사한 결과, 이름에 AI 표시를 한 채널은 2개(0.8%)뿐**이었다
(2026-08-20 실측). balcony9 · cherry music · soft hour · jazzpli · 힐링음악 처럼
사람이 만든 채널과 구별할 수 없는 이름을 쓴다. 흔한 단어는 music · lofi · pop · cafe · chill 로,
정상 음악 채널과 완전히 겹친다.

그래서 **제목·채널명 키워드만 보는 방식은 원리적으로 대부분을 놓친다.** 키워드는 노골적인 것만
걸러내는 1차 그물이고, 실제 방어선은 유튜브 공시 배지에 기반한 **시드 목록과 채널 학습**이다.

**판별 근거의 핵심은 유튜브 자체 AI 공시 배지**다. 제목에 "AI"가 한 글자도 없는 채널
(balcony9, cherry music, soft hour 등)도 유튜브가 붙인 라벨로 정확히 잡힌다.
배지의 **글자는 언어마다 다르다** — AI(한국어·영어·일본어) · IA(스페인어·프랑스어) ·
KI(독일어) · ИИ(러시아어) · एआई(힌디어). 그래서 글자가 아니라 배지의 아이콘 종류로
판별한다. 6개 로케일에서 동일하게 잡히는 것을 확인했다.
추측성 신호(업로드 속도 등)는 오탐이 커서 쓰지 않는다 — 실측에서 예능·스포츠 채널까지
AI로 판정되는 것을 확인했다.

## 자동재생은 절대 끊기지 않는다

DOM에서 카드만 숨기는 방식은 자동재생을 막지 못한다(유튜브 자동재생은 DOM이 아니라 내부 응답
데이터를 쓴다). 그래서 이 익스텐션은 **데이터가 도착하는 지점에서 거른다**:

- `ytInitialData` 세터 후킹 (첫 로드)
- `/youtubei/v1/next`·`browse`·`search` 응답 필터링 (이후 모든 로드)
- 자동재생 대상이 걸러졌으면 **살아남은 첫 정상 영상으로 조용히 승계**

재생을 멈췄다가 이동하는 게 아니라 애초에 AI 영상이 큐에 들어가지 않으므로,
사용자는 아무 끊김도 느끼지 못한다.

**안전 원칙**: 모든 후킹은 try/catch로 감싸고, 실패하면 원본 데이터를 그대로 통과시킨다.
필터가 죽는 한이 있어도 유튜브는 멀쩡해야 한다.

검색 결과에서 눌러 들어간 경우처럼 사전에 못 막는 상황에서는, 재생 직후 판별해 바로
다음 곡으로 넘긴다(팝업에서 끌 수 있음).

## 피드백 (애드블록 방식)

- **툴바 배지** — 이 페이지에서 걸러낸 개수
- **팝업**
  - 이 페이지 / 오늘 / 누적 카운트 (오늘 카운트는 자정에 리셋, 누적은 유지)
  - **방금 걸러낸 항목** — 무엇을 왜 걸렀는지 한국어로. 각 줄에서 바로 "허용"으로 되살린다.
    같은 영상은 한 줄로 합치고, 최근 50건까지 남는다.
  - **채널 관리** — `학습됨`(확장이 스스로 알아낸 채널) / `직접 차단` / `허용` 3탭
  - 스위치: 전체 끄기, 재생 중 자동 넘김, 알려진 AI 채널 목록 사용
- **건너뛴 뒤 알림** — 자동으로 넘어갔을 때 하단에 조용히 뜬다.
  "AI 음악을 건너뛰었습니다 · 채널명" + **되돌리기**(그 채널을 허용하고 원래 영상으로 복귀).
  6초 뒤 사라지고, 전체화면에서는 재생 컨트롤을 가리지 않도록 띄우지 않는다.
- **시청 페이지 배너** — 자동 넘김을 껐거나 넘길 곳이 없을 때만 뜬다.
  재생은 멈추지 않고 [이 채널 차단] [허용] 버튼만 제시한다.

판별 사유는 화면에 **한국어로만** 나간다(`유튜브가 AI로 표시`, `알려진 AI 채널`,
`제목·채널명에 "AI가 만든"`, `… · 재생 중 건너뜀`). 내부 코드가 새어나오면 테스트가 실패한다.

## 개발

```bash
npm test          # 판별 로직·자동재생 승계·실측 구조·UI 문구 검증 (35건)
npm run build     # 테스트 통과 시에만 dist/noaimusic-<버전>.zip 생성
npm run sync      # heuristics.iso.js 사본 갱신 (test 가 먼저 실행한다)
```

`tools/harvest.js` 는 AI 채널 수집기다. CDP 로 붙은 크롬에서 검색어를 돌며
유튜브 AI 공시 배지를 확인해 `data/ai-channels.json` 을 키운다.

- `src/heuristics.js` — 판별 코어 (MAIN world·content·node 테스트 공유, DOM/chrome API 미사용)
- `src/page.js` — MAIN world. 데이터 레이어 필터링
- `src/content.js` — ISOLATED. 설정 전달·DOM 안전망·프로파일링·통계
- `src/background.js` — 배지·통계·채널 프로파일링
- `src/lists.js` — 차단·허용 목록 저장소 (팝업·콘텐츠 공용)
- `data/seed-channels.json` — Soul Over AI 스냅샷 (채널 ID)
- `data/ai-channels.json` — 유튜브 AI 공시로 직접 수집한 채널

`npm test` 는 `npm run sync` 를 먼저 돌려 `src/heuristics.iso.js` 를 갱신한다.
**크롬은 같은 파일 경로를 MAIN/ISOLATED 두 월드에 중복 주입하지 않는다**(2026-08-19 실측).
그래서 격리 월드용 사본을 따로 두며, 두 파일이 어긋나면 테스트가 실패한다.

## 저장소

| 무엇 | 어디 | 왜 |
|---|---|---|
| 설정 3개 (켜기·자동넘김·시드사용) | `storage.sync` | 작고 거의 안 바뀌어 기기 간 동기화가 이득 |
| 차단·허용 목록 | `storage.local` | **sync 는 항목당 8KB 라 채널 100여 개에서 저장이 조용히 실패한다**(실측). local 은 2,000개도 112KB 로 여유롭다 |
| 학습 결과·통계·최근 목록 | `storage.local` | 계속 커지고 기기마다 다시 쌓이면 되는 값 |

구버전이 `sync` 에 남긴 목록은 처음 읽을 때 `local` 로 옮기고 `sync` 에서 지운다.

## 데이터 출처

`data/ai-channels.json` 은 한국어·영어 음악 검색어 294종의 상위 결과 영상 1,782편을 열어
**유튜브가 직접 붙인 AI 공시 배지**를 확인해 모은 256개 채널이다. 추측 판정은 넣지 않았다.
이 중 아래 Soul Over AI 목록과 겹치는 건 4개뿐 — 영어권 DB가 한국 AI 음악 채널을
거의 덮지 못한다는 뜻이다.

실측(2026-08-20): 음악 검색어 5종에서 확장을 켜면 결과 카드가 119개 → 96개로,
**약 19%가 걸러진다.**

**시드 목록을 완전히 끄고 학습만으로도 비슷하다** — 같은 검색 5종에서 카드 114개 중
20개(18%)를 스스로 걷어냈고, 그 과정에서 채널 48개를 확인해 11개를 AI 로 알아냈다.
즉 미리 아는 목록이 없어도 쓰는 동안 스스로 채워 넣는다. 다만 즉시는 아니고,
화면에 뜬 채널을 하나씩 확인하는 만큼 시간이 걸린다(수십 초 단위). "로파이 플레이리스트" 처럼 AI가 몰린 검색어에서는 절반 가까이 사라진다.
스페인어 "música generada por IA playlist" 검색은 13개 중 12개가 새어나갔으나 지금은 전부 걸러진다.

`data/seed-channels.json` 은 [Soul Over AI](https://souloverai.com) 프로젝트
([GitHub](https://github.com/xoundbyte/soul-over-ai))의 `dist/artists.json` 스냅샷에서
YouTube 채널 ID만 추출한 것이다. **CC BY 4.0** 라이선스. 원본 프로젝트는 2026-02-16 이후
갱신이 중단되었으므로 이 목록은 정적 스냅샷이며, 이후 등장한 채널은 휴리스틱과 프로파일링이 담당한다.
